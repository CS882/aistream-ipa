# AIStream 影视 · 原生安装包构建说明

> 本文件说明如何产出四个**可安装的原生安装包**：Windows `.exe`、iOS `.ipa`、安卓手机 `.apk`、Android TV `.apk`。
> 原有浏览器/WebView 入口仍保留，用于开发调试；安装包使用同一份 Web 内核（`npm run sync:assets` 同步）。

## 二、一键构建（Windows）

```bat
build-all.bat
```

或分步：

```bash
npm install                 # 首次需要；安装 electron + electron-builder
npm run sync:assets         # 同步 Web 资源到 web/ 与两个 assets/www
npm run dist:win            # Windows 安装程序 + 便携版
npm run dist:android        # 手机 APK
npm run dist:tv             # TV APK
npm run build:all           # 三个一起
```

构建依赖（本机已具备）：Node 18+、JDK 17、Android SDK（platforms;android-34 + build-tools;34.0.0）、Python 3。

> `.apk` 采用**零 Gradle / 零 Maven 依赖**的构建方式：`scripts/build-apk.py` 直接调用 SDK 自带的 `aapt2 → javac → d8 → zipalign → apksigner`，离线可重复，不需要下载 Gradle Wrapper 或第三方依赖。

## 三、Windows `.exe`

- 技术：Electron 31 + electron-builder（NSIS + portable 双目标）。
- 主进程 `electron-main.cjs` 内置一个仅监听 `127.0.0.1` 的本地静态服务，用 http 协议加载 `desktop.html`，保证 ES Modules 正常（Electron 下 `file://` 会阻止模块加载）。
- 窗口默认 1440×900，加载桌面键鼠布局（侧栏 + 悬浮卡片 + 详情抽屉 + 快捷键）。
- 打包内容已核验：asar 内含 `desktop.html` / `mobile.html` / `tv.html` / `electron-main.cjs` / `src/**` / `public/**`。
- 安装：双击 `AIStream-Setup-1.0.0.exe` 按向导安装；或直接运行 `AIStream-Portable-1.0.0.exe`。
- 当前**未经代码签名**，首次运行会出现 Windows SmartScreen 提示（待补充项 `release.winSigning`）。

## 四、安卓手机 `.apk` 与 TV `.apk`

### 共同点

- 标准 Gradle 工程 `android/` 与 `android-tv/`（可用 Android Studio 打开），同时支持上述零依赖构建。
- 原生壳用系统 `WebView`，App 内起一个**只监听 127.0.0.1** 的极简静态服务，把 `assets/www` 以同源 http 提供，让 ES Modules / Service Worker 正常工作。
- 零第三方 Android 依赖，不需要 AndroidX / WebViewAssetLoader / Maven 仓库。
- `android:usesCleartextTraffic="true"`：实测站点只提供明文 HTTP（HTTPS 握手失败），且前端通过 `127.0.0.1` 同源代理访问，因此原生壳保留明文许可；若后续启用 HTTPS 可收紧。

### TV 版是**真正的 TV 适配**，不是手机包改名

已核验 `aapt dump badging` 输出：

```
application: label='AIStream 影视 TV' banner='res/drawable-xhdpi-v4/tv_banner.png'
leanback-launchable-activity: name='com.aistream.pending.tv.MainActivity'
  uses-feature: name='android.software.leanback'
  uses-feature: name='android.hardware.screen.landscape'
  uses-feature-not-required: name='android.hardware.touchscreen'
```

| 适配项 | 落地位置 |
|--------|---------|
| TV 桌面入口 | `android-tv/.../AndroidManifest.xml` → `LEANBACK_LAUNCHER` |
| Leanback 声明 | `uses-feature android.software.leanback required=true` |
| 无触摸屏可安装 | `hardware.touchscreen / camera / location / ... required=false` |
| 横屏大屏 | Activity `screenOrientation="landscape"`；`tv.css` 20px 基准字号 + 3.2vh/3.6vw overscan |
| TV Banner | `res/drawable-xhdpi/tv_banner.png`（320×180 占位，待替换为正式素材） |
| 遥控器方向键 | `MainActivity.dispatchKeyEvent` 把 `DPAD_UP/DOWN/LEFT/RIGHT` 注入为 `ArrowUp/Down/Left/Right` DOM 事件 |
| OK / 确认 | `DPAD_CENTER` / `ENTER` → `Enter`，驱动 Web 端 `FocusManager` |
| BACK | 先调用 `window.__onRemoteBack()`：有详情/搜索/关键词则在 Web 端消费，否则原生 `finish()` 退出 |
| 搜索键 / 播放键 | `KEYCODE_SEARCH` → `F3`；`MEDIA_PLAY_PAUSE` → `MediaPlayPause` |
| 内容组织 | 加载 `tv.html?platform=tv`（左侧大焦点导航 + 横向货架 Rows + 全屏沉浸详情），不是手机三列网格 |

> 不同厂商遥控器的 keyCode 可能有差异，真机需核对（待补充项 P-29）；映射表集中在 `MainActivity.dispatchKeyEvent` 与 `tv.js` 顶部的 `KEY_ACTION / KEYCODE_ACTION`。

### 安装

```bash
adb install -r dist/AIStream-Mobile-1.0.0.apk
adb install -r dist/AIStream-TV-1.0.0.apk
# TV 设备：adb connect <TV_IP>:5555 后安装；TV 桌面会出现「AIStream 影视 TV」横幅入口
```

当前两个 APK 使用 `~/.android/debug.keystore` 签名，**仅供测试安装**；上架需正式签名密钥（待补充项 `release.androidSigning`）。

### 包名占位（重要）

| 工程 | 当前包名 | 说明 |
|------|---------|------|
| `android/` | `com.aistream.pending.mobile` | 构建占位，发布前必须替换 |
| `android-tv/` | `com.aistream.pending.tv` | 构建占位，与手机版不同包名，可同时安装 |

替换位置：两个 `AndroidManifest.xml` 的 `package`、两个 `app/build.gradle` 的 `namespace`/`applicationId`、两个 `MainActivity.java` 的包名与目录。

## 五、iOS `.ipa`（平台限制）

**Windows 无法产出 `.ipa`**：`xcodebuild`、`codesign`、iOS SDK 与签名工具链只由 macOS + Xcode 提供，这是 Apple 的平台限制，与本项目代码无关。因此本交付提供的是**在 Mac 上一键产出 `.ipa` 的完整链路**：

```bash
# 在 macOS + Xcode 上执行（需 Apple Developer 账号）
APP_ID=com.yourcompany.aistream TEAM_ID=ABCDE12345 bash ios/build-ipa.sh
```

脚本会自动完成：安装 Capacitor CLI/iOS → 同步 `web/` → 写入 Bundle ID → `cap add ios` → `xcodebuild archive` → `xcodebuild -exportArchive`，产出 `dist/ipa/AIStream.ipa`。

相关文件：

| 文件 | 用途 |
|------|------|
| `ios/build-ipa.sh` | Mac 一键 archive + 导出 |
| `ios/ExportOptions.template.plist` | 导出配置（`method=development`，上架改 `app-store`） |
| `capacitor.config.json` | `webDir: "web"`，`appId` 为空（待补充项 P-27） |
| `public/icon.png` | 占位应用图标（待补充项 P-35） |

需要补充：`APP_ID`（Bundle ID）、`TEAM_ID`、签名证书/描述文件（待补充项 `release.iosTeamId` / `release.iosSigning`）。

> 若没有 Mac，可选替代：使用云构建服务（如 GitHub Actions macOS runner / CI 上的 Xcode）执行同一个 `ios/build-ipa.sh`。

## 六、原生打包新增待补充项

以下 4 项已追加进 `src/core/datasource.js` 的 `PENDING_ITEMS` 与 [00-待补充项清单.md](./00-待补充项清单.md)（发布分组），与界面「N 项待补充」计数一致：

| 配置键 | 内容 | 不补充的后果 |
|--------|------|-------------|
| `release.iosTeamId` | Apple Developer Team ID | Mac 上无法自动签名、导出 `.ipa` |
| `release.iosSigning` | iOS 证书 / Provisioning Profile / 导出方式 | `.ipa` 无法真机安装或上架 |
| `release.androidSigning` | 安卓正式签名密钥 | 只能测试安装，无法上架与版本升级 |
| `release.winSigning` | Windows 代码签名证书 | `.exe` 首次运行有 SmartScreen 提示 |

另外，正式应用图标 / 启动图 / TV Banner 均为**占位素材**（由 `scripts/generate-icons.py` 生成），归入 P-35；正式包名归入 P-27 / P-28。
