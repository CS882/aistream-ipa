## 一、探测结论速览

| 项目 | 实测结果 |
|------|---------|
| 域名解析 | 可达（AAAA 记录） |
| 协议 | **HTTP 可用**；HTTPS 在该端口握手失败（`SEC_E_INVALID_TOKEN`），说明只提供明文 HTTP |
| 首页 | `200`，标题 `AIStream 影视 · AI 影视`，是一个**登录门禁页**（`gate.js`） |
| 服务类型 | **自研 AIStream 影视聚合后端**，不是 MoonTV / 苹果 CMS 采集接口 |
| 静态资源 | `gate.js` / `app.js` / `player.js` / `style.css` 可公开读取（接口规范由此得到） |
| 公开接口 | `GET /api/public` → `200`，无需登录 |
| 其它接口 | 未登录一律 `401 {"error":"未登录"}` |
| 鉴权 | `POST /api/auth/login` → `{token}`；之后 `Authorization: Bearer <token>` |
| 注册 | `/api/public` 返回 `regEnabled: true`、`inviteRequired: false` |
| CORS | 响应头**无** `Access-Control-Allow-Origin`；`X-Frame-Options: DENY` |
| 结论 | 浏览器/WebView **直连必被 CORS 拦截**，必须走同源代理 |

## 二、关于「类似 MoonTV」

MoonTV 通常对接苹果 CMS 采集接口（`/api.php/provide/vod/?ac=list` 等）。实测发现**你的站点不是这类接口**：

| 路径 | 实测状态 |
|------|---------|
| `/api.php/provide/vod/?ac=list` | 404 |
| `/api.php/provide/vod/?ac=videolist` | 404 |
| `/api.php/provide/vod/` | 404 |
| `/api/home` | 401 未登录（存在） |
| `/api/search` | 401 未登录（存在） |

因此没有套用 MoonTV 的采集协议，而是**按你站点自己的 `/api/*` 规范对接**，并把实测到的协议、路径、参数名、字段名全部内置在 `src/core/datasource.js`。

## 四、跨域问题与同源代理（跑通的关键）

站点响应**没有** `Access-Control-Allow-Origin`，因此：

- 浏览器从 `http://127.0.0.1:5173` 直接 fetch `http://fnos.jiulingkeji.asia:8890/api/home` → 被 CORS 拦截；
- Electron 渲染进程、Android WebView 同理。

**解决办法**：前端只请求同源相对路径 `api/xxx`，由各端本地服务转发到内容源，并透传 `Authorization` 与 POST 请求体。

| 端 | 代理实现位置 | 转发目标 |
|----|-------------|---------|
| 浏览器 / 本地预览 | `server.js` → `proxyApi()` | `http://<host>/api/*` |
| Windows `.exe` | `electron-main.cjs` → `proxyApi()` | 同上 |
| 安卓手机 `.apk` | `android/.../MainActivity.java` → `proxyApi()`（HttpURLConnection） | 同上 |
| Android TV `.apk` | `android-tv/.../MainActivity.java` → `proxyApi()` | 同上 |
| iOS `.ipa` | 需在 macOS 打包时配置 Capacitor 同源代理（见 `docs/05`） | 同上 |

代理实测验证（`http://127.0.0.1:5174`）：

```
GET  /api/public                     → 200 {"siteName":"AIStream 影视", ...}
GET  /api/home  (Bearer 无效)         → 401 {"error":"未登录"}   ← 证明 Bearer 头已透传
POST /api/public (带 JSON body)       → 401 上游门禁响应        ← 证明 POST 方法与请求体已透传
```

## 五、现在怎么跑通

### 1）启动（已内置你的域名，无需再配置）

```bash
npm start                 # 或 build-all.bat 重新打四端安装包
```

四端入口：`/desktop.html`、`/mobile.html`、`/tv.html`、`/`（自动分发）。

### 2）登录（**唯一需要你做的一步**）

站点 `needLogin=true`，所有 `/api/*` 都要 Bearer Token。打开任意端会看到登录界面：

- 输入你在主站的用户名密码 → 点「登录」；
- 或点「注册新账号」（站点 `regEnabled:true`、`inviteRequired:false`）；
- 也可以直接用主站已有账号登录。

> 本项目**不内置、不猜测、不上传**任何账号密码；登录接口有「连续失败 5 次锁定 15 分钟」保护，请勿反复尝试错误密码。

### 3）登录成功后的自动流程

```
POST api/auth/login → 保存 token
   ↓
GET api/home → 真实栏目 columns[] 变成顶部频道
   ↓
浏览：columns[].items → 海报卡片（poster 经 api/dimg 代理）
搜索：api/search?q= → collect[]
详情：~~使用列表中的真实条目（站点无独立详情接口）~~ → **后续三次实测已找到 `api/up/detail?id=&phase=1`，提供 description / directors / actors / rating，详见 [12-流中转与播放页重构.md](./12-流中转与播放页重构.md)**
播放：api/play?sid=&vid= → results[].sources[].episodes[].url → 可点击的播放入口/剧集列表
```

四端共用同一份 `src/core/store.js`，所以内容完全一致，只是布局与操作方式不同。
