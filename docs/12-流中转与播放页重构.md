# 12 · 流中转、播放页重构与切换卡顿修复

> 本轮针对你列出的 P0/P1 清单 + 三张截图，逐项落地。
> 全部结论来自对 `fnos.jiulingkeji.asia:8890` 的再次实测与本地运行时验证，未使用任何示例影视数据。

## 一、P0-1 服务端流中转 `/api/proxy?u=`

### 实现

四端各一份同源中转，接口签名一致：

```
GET /api/proxy?u=<encodeURIComponent(真实片源地址)>
```

- **协议**：同时支持 `http:` / `https:`（按 URL 选择 node http / https 客户端；安卓壳用 `HttpURLConnection`）
- **重定向**：手动跟随最多 5 跳（302/307 常见于 CDN 防盗链）
- **Range**：透传 `Range`，回传 `206 / Content-Range / Accept-Ranges`，mp4 拖动进度才有意义
- **m3u8 重写**：命中 `mpegurl` 或 `.m3u8` 时，把清单里的分片地址与 `#EXT-X-KEY / #EXT-X-MAP / #EXT-X-MEDIA` 的 `URI="..."` 全部改写为 `/api/proxy?u=...`，否则 hls.js 会以本地源为基准解析相对路径而 404
- **安全**：仅允许 http/https；拒绝代理 `localhost / 127.* / ::1`，避免把本机服务当跳板递归

改动文件：`server.js`、`electron-main.cjs`、`android/.../MainActivity.java`、`android-tv/.../MainActivity.java`。

### 实测（本地 5173）

| 用例 | 结果 |
|---|---|
| 公开 HLS 主清单 | `200`，5 条子清单地址被改写为 `/api/proxy?u=` |
| 二级子清单 | `200`，分片 `.ts` 被改写 |
| 真实 `.ts` 分片 + `Range: bytes=0-2047` | `206 Partial Content`，`content-range: bytes 0-2047/1915156` |
| 站点自身 `http://fnos.../vendor/hls.min.js` | `200`（http 上流可用） |

### 播放器接入

- 设置新增 **「跨域片源走本机中转」**（默认开）
- 判定：`new URL(u).origin !== location.origin` → 走 `/api/proxy`；站点自身的 `api/iptv/stream`、`api/dimg` 保持直连
- HLS 的 `xhrSetup` 只给内容源 `/api/*` 加 Bearer，**不给中转地址加**，避免 token 被带到第三方
- 跨域判定基于原始地址（不是中转后的地址），所以 `isM3u8()` 仍然正确

## 二、P0-2 地区字段标准化

`src/components/filters.js` 用**两层映射**替代原来的 `area.includes(country)`：

1. **单项别名**：`美剧/美片/好莱坞 → 美国`、`港剧/港片/TVB → 中国香港`、`台剧 → 中国台湾`、`内地/国语 → 中国大陆`、`日漫/日剧 → 日本`…
2. **大区展开**：内容源常返回笼统值
   - `欧美` → 美国、英国、法国、德国、意大利、西班牙、加拿大、澳大利亚、爱尔兰、瑞典、丹麦、巴西
   - `华语` → 中国大陆、中国香港、中国台湾、中国澳门
   - `日韩` → 日本、韩国
   - `港台` → 中国香港、中国台湾
   - `亚洲` → 华语 + 日韩 + 泰国、印度

实测：`area=欧美` 选「美国 / 英国」为 true；`area=华语` 选「中国香港 / 中国台湾」为 true；`area=港台` 选「中国台湾」为 true。

排序新增 **评分**（实测 `upCard` 使用 `it.score`）；**热度**仍置灰，因为站点没有热度字段。

## 三、P0-3 筛选覆盖范围

实测 `api/up/catalog` 只接受 `kind / limit / page`，没有 `area / year / sort`。因此：

- 不伪造参数，改为**多页加载 + 本地标准化匹配**（最多 4 页）
- 筛选面板底部如实标注：`已加载 N 条 · 国家/年份按内容源真实 area/year 标准化匹配；热度字段站点未提供`
- 新增按钮 **「加载更多（扩大筛选范围）」**，点击后追加下一页并去重

## 四、P1-4 续播键改为「内容 id + 集序号」

旧实现：`标题|集名` —— 片名带季数、换线路后集名不同就会丢进度。

新实现：

```js
key = `${contentId || title}#${epNo}`     // epNo 从「第 12 集」解析出 12，解析不到用序号
storage: aistream_resume_v2
```

- `contentId` 来自 `resolvePlay()` 返回的 `contentId`（上游 `av_` token 或站点 vid）
- 换线路时同一集的 `epNo` 不变 → 仍能续播
- 最多保留 60 条，播放中每 10 秒、暂停、关闭前各存一次

## 五、P1-5 TV 登录：遥控器虚拟键盘

实测站点只有 `api/auth/login`（用户名 + 密码），**没有扫码 / 设备码 / 短信接口**，所以扫码登录无法凭空实现（已登记为 P-02）。

TV 端改为：

- 10 列虚拟键盘：数字、26 字母、`.` `-` `_` `@`
- 功能键：大写 / 退格 / 清空 / 显示密码
- 焦点记忆：记住最后停留的输入框（用户名 / 密码），重渲染后仍能继续输入
- 全部键为 `data-focusable + data-zone="auth"`，接入 TV `FocusManager`，方向键 + OK 即可输入

实测：TV 登录页渲染 44 个键，点击 `a`、`b` 后用户名为 `ab`。

> 若站点后续提供设备码 / 扫码接口，只需替换 `auth.js` 中的登录方式，虚拟键盘可保留为兜底。

## 六、P1-6 详情页简介 / 演职员

之前判断「站点无详情接口」是错的。三次实测在 `player.js` 中找到：

```
GET /api/up/detail?id=av_xxx&phase=1
→ detail: { title, poster_url, backdrop_url, year, area, language,
            rating|score, genres[], directors[], actors[],
            description, remarks, episode_count, season_count }
→ episodes: { episodes|items|list: [{name,token}] }   ← 用 token，真实地址需 /api/up/resolve
```

现在：

- `fetchDetail()` 优先请求该接口，把简介 / 导演 / 主演 / 类型 / 评分 / 集数 / 更新文案合并进条目
- 详情页（桌面抽屉、移动整页、TV 全屏）展示类型 / 导演 / 主演标签与完整简介
- `resolvePlay()` 对 `av_` 条目先用该接口拿分集 token，播放时再调 `/api/up/resolve?token=` 换取真实地址；失败才回退 `api/play`（详见 docs/13）
- 点击卡片时顺带调用 `api/up/warm?id=` 预热

## 七、截图问题：切换分类「下方卡住」

### 根因（三条叠加）

1. `renderContent` 的缓存 key 里**没有 `state.loading`**，切换后仍在加载却没有任何视觉反馈 → 看起来「按了没反应」
2. 切换分类时**不清空旧内容**，而纪录片 / 短剧接口本身慢（8 秒超时）→ 旧内容静止 8 秒
3. 请求**没有取消机制**：连点分类时慢请求仍在跑，还可能覆盖新分类（虽有序号丢弃结果，但网络仍排队）

### 修复

- **乐观切换**：`setChannel` 立即清空旧内容 → `status=loading` → `loadingChannel=当前分类`
- **骨架屏**：无缓存时立刻渲染 12 张骨架卡（桌面）/ 6 张（移动）/ 提示行（TV）
- **细进度条**：`loadingStrip(state)` 显示「正在加载『纪录片』· 正在向内容源请求…」，2.6 秒后自动加一句「站点聚合较慢，已并行尝试回退…」；不再整块压暗
- **请求取消**：`AbortController` + `refreshSeq`，新请求取消上一次在飞请求
- **缓存优先**：有缓存直接换内容，不发请求
- 渲染 key 纳入 `loading / slowHint / filter.country`（顺带修了筛选字段改名后不重绘的问题）

### 实测

模拟「纪录片接口 900ms 慢返回」：

```
点击后 120ms：strip=true  skeleton=12  chipActive=true  旧卡片=0
1500ms 后 ：stripGone=true  新内容已渲染
```

## 八、截图问题：播放页选集重叠 / 线路被挡 / 2000+ 集

### 根因

- 侧栏是 `grid` + 选集固定 `max-height:48~58vh`，与下方「播放信息」抢高度 → 重叠
- 线路是原生 `<select>`，在 TV 上无法展开，桌面也被标题压住
- 2249 集全量渲染 → 列表巨大、滚动卡、性能差

### 重构（腾讯视频式）

```
右侧面板
├─ 标签：选集（共 N 集） / 影片信息
├─ 线路：横向标签按钮（可横滑，TV 可直接焦点选择）
├─ 选集：flex:1 + min-height:0 + 独立滚动，只渲染当前页
└─ 分页：固定底部（‹ 1 … 7 8 9 … 38 ›）
```

- 每页集数：桌面 60 / TV 40 / 移动 24
- 手动翻页不会被「对齐当前集」打回（仅在换集 / 换线路时对齐）
- 「播放信息」不再挤在选集下方，而是独立标签页，展示评分 / 年份 / 地区 / 类型 / 集数 / 线路 / 导演 / 主演 / 简介 / 内核说明
- TV 焦点导航改为**几何最近元素**（方向键在标签、线路、选集网格、分页间都成立）

实测（300 集、2 条线路）：

```
EPS_ON_PAGE=60 | PAGER=4 | CHIPS=2 | TABS=2 | OVERLAP=false
PROXIED=true | 翻页 第1集 → 第61集 | 信息页 简介+3 个演职员标签
```

## 十二、iOS 与「内容源网关」

`.apk` 与 `.exe` 都内嵌了本地服务（静态资源 + `/api/*` + `/api/proxy`），所以开箱即用。
**iOS 的 Capacitor 壳没有内嵌 Node 服务**，`/api/*` 与 `/api/proxy` 在 `capacitor://localhost` 下无处可转。

本轮新增了一个可选的 **「内容源网关」**（设置 → 播放 → 内容源网关）：

1. 在电脑 / NAS 上运行本项目：`HOST=0.0.0.0 PORT=5173 node server.js`
2. iOS 应用内设置填入 `http://<该机器局域网 IP>:5173`
3. 之后所有 `api/*`、海报 `api/dimg`、片源 `/api/proxy` 都会指向该网关

注意事项：

- 网关与手机需在同一局域网；路由器要放行 5173
- iOS 若使用明文 `http`，需要在 Xcode 工程的 `Info.plist` 加 ATS 例外（`NSAllowsArbitraryLoads` 或针对该 IP 的例外），否则系统会拦截
- 更彻底的做法是在 iOS 工程内用原生 `URLSession` 实现同样的转发（与安卓壳的 `proxyStream` 等价）。这属于 iOS 原生开发工作量，未在本轮实现

这一步是「iOS 端能连上内容源」的最低成本方案；若你希望 iOS 完全离线自带代理，需要在 Mac 上补一个 Capacitor 原生插件（可另开一轮做）。
