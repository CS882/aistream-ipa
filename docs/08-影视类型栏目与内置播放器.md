# AIStream 影视 · 影视类型栏目、快捷入口修复与内置播放器

> 2026-11-15 深夜改版。三项需求：① 顶部栏目按电影 / 电视剧 / 动漫 / 综艺 / 短剧 / IPTV 等影视类型区分；② 修复「我的」快捷入口；③ 内置播放器。
> 所有接口、参数、字段均来自对 `fnos.jiulingkeji.asia:8890` 的**二次实测**（公开静态文件 `app.js` / `player.js` / `player.html`），没有假设值。

## 一、为什么之前显示「栏目 1 ~ 栏目 13」

`/api/home` 返回的 `columns[]` 是**采集源栏目**（站点后台配置的资源站），标题就是「栏目 1…栏目 13」。上一版把它直接当成了顶部频道，所以看起来像占位符。

站点自己的 `app.js` 里其实有两套东西：

- 侧栏「分类」：`rec / movie / series / anime / variety / short / vod / doc`，`KINDNAME = { movie:'电影', series:'剧集', anime:'动漫', variety:'综艺', short:'短剧', doc:'纪录片' }`
- 侧栏「直播」：`iptv`、`sportslive`
- 按类型取内容的真实接口是 **`api/up/catalog?kind=<kind>&limit=48&page=1`**（`loadKind()`），返回 `{items:[...], pageSize}`
- `api/home/cat?idx=&t=` 只是「某个首页栏目内的分类筛选」，不是全局影视类型分类 —— 上一版把 `kind` 塞给 `t` 是错的，所以总是走回退

## 二、顶部栏目改造

`src/core/config.js` 的 `CHANNELS` 固定为影视类型（显示名按需求方要求用「电视剧」，内部 id 仍用站点实测的 `series`）：

| 频道 | id / source | 真实数据来源 |
|------|-------------|-------------|
| 推荐 | `rec` / `home` | `api/home → columns[].items[]` |
| 电影 | `movie` / `catalog` | `api/up/catalog?kind=movie&limit=48&page=1` |
| 电视剧 | `series` / `catalog` | `api/up/catalog?kind=series&...` |
| 动漫 | `anime` / `catalog` | `api/up/catalog?kind=anime&...` |
| 综艺 | `variety` / `catalog` | `api/up/catalog?kind=variety&...` |
| 短剧 | `short` / `catalog` | `api/up/catalog?kind=short&limit=12&page=1`（站点短剧每页 12 条） |
| 纪录片 | `doc` / `catalog` | `api/up/catalog?kind=doc&...` |
| 点播 | `vod` / `official-vod` | `api/official-vod → list[]` |
| IPTV | `iptv` / `iptv` | `api/iptv → channels[]`，播放 `api/iptv/stream?ch=&token=` |

- 登录后读 `api/config` 的 `views` / `iptv.enabled` / `officialVod.enabled`，按站点**真实权限**隐藏未开放项；接口不可用时保留全部分类，避免误杀。
- 分类接口失败时只回退 `/api/home` 的真实内容并在界面提示；**不再**用 `api/home/cat`（首页栏目内筛选）冒充全局影视类型，避免拿错内容。
- `mapItem` 扩展支持站点实测字段 `poster_url / carousel_url / backdrop_url / normalized_title / area / content_kind`，海报仍走 `api/dimg?u=` 代理。
- 站点的「体育直播」是第三方网页 iframe 嵌入，四端无法统一承载，未纳入频道（不作为假入口）。

## 三、快捷入口 BUG 修复

**问题**：`extras.js` 的 `summarize()` 把接口原始 JSON 的前 8 个键值直接摊开，于是「积分中心」显示成 `points 10000000000019 / vip [对象] / growth [对象]`，点击入口只是打印数据，不是进入功能。

**修复**：`datasource.js` 的 `fetchExtra(id)` 按站点实测结构返回**结构化视图**，`extras.js` 按 `kind` 渲染：

| 入口 | 真实接口 | 现在的界面 |
|------|----------|-----------|
| 我的追剧 | `api/weekly → days[]` | 按天分组的周片单 |
| 积分中心 | `api/points/me → points/vip/checkin/invite` | 积分数、会员身份、倍率、签到状态、邀请码 |
| 我的预约 | `api/preview/reserved → items[]` | 影视海报卡片（可详情 / 播放） |
| 历史记录 | `api/history → items[]` | 影视海报卡片 |
| 我的收藏 | `api/fav → items[]` | 影视海报卡片 |
| IPTV 直播 | `api/iptv → channels[]` | 直播频道卡片，点击直接播放 |

卡片带真实 `id`，点击走与首页一致的 `openDetail` / `requestPlay`；TV 端这些卡片都带 `data-focusable`，遥控器可聚焦。新增「收起」按钮，三端事件委托均已接入。

## 四、内置播放器

`src/components/player.js`，由 `chrome.js` 统一注册，四端共用业务逻辑、按端独立布局：

- **格式**：`m3u8` → 项目内置 `public/vendor/hls.min.js`（站点同款 606 KB，离线可用，已实测 `Hls.isSupported()===true`）；`mp4` 等直链 → 原生 `<video>`；iOS 优先原生 HLS。
- **能力**：选集、线路切换（按 `sources.from` / `results.name` 分组）、播放暂停、进度点击拖动、音量 / 静音、全屏、自动下一集、跳过片头片尾、外部播放器打开、复制地址。失败时显示真实错误并提供回退，不伪造可播放内容。
- **布局**：桌面 = 左侧大画面 + 右侧线路/剧集栏（键鼠）；移动 = 上半屏画面 + 下半屏横滑剧集（触控目标加大，含安全区）；TV = 10-foot 全屏画面 + 右侧大焦点控制区，按钮字号 19px、焦点环 4px。
- **遥控**：播放器在 capture 阶段接管方向键 / OK / BACK，优先于三端全局快捷键与 TV `FocusManager`；BACK 先关播放器再退出 App（`window.__aisPlayerBack` ↔ `tv.js` 的 `__onRemoteBack`）。原生壳本来已具备免手势播放、混合内容、硬件加速与明文流量设置。
- **设置**：`playMode` 默认改为 `内置播放器（推荐）`，仍可切「每次询问 / 外部播放器 / 仅复制地址」；`autoNext`、`skipIntro`、`skipOutro` 现在真正生效。

### 独立复核后的修复

质量角色只读复核抓到并已修复：

1. **功能阻断**：三端 `lastContentKey` 未包含 `state.extra`，导致点快捷入口后界面永远停在「正在读取…」，切换入口 / 收起也无反应。已把 `extra.id / loading / ok` 纳入三端重绘键；用 iframe 真实点击「我的 → 积分中心」验证：`LOADING_STUCK=false | RESULT_SHOWN=true | EXTRA_CARD=true | RAW_JSON_GONE=true`。
2. **交付门禁**：自检断言要求对象字面量精确闭合导致误报；已放宽为前缀匹配，自检 30/30。
3. 附带修：积分卡字段统一转义、HLS 加载失败可重试、TV 增加「上一线路 / 下一线路」遥控按钮（不依赖 `<select>` 展开）、启动台过时文案（骨架占位态）改为实测接入说明、注释与实现同步。

## 六、仍需需求方确认

1. 在应用内登录一次，点几个新分类（尤其「电视剧」「综艺」「短剧」）看是否出真实内容；若界面提示「该分类暂无独立条目」，把提示发来，按站点实际返回值调整 `kind` 或 `limit`。
2. 播放时若出现「片源网络错误（可能为跨域或线路失效）」，说明该线路 m3u8 未开放浏览器跨域；需要决定是否加服务端流中转（站点自身对部分线路用 `direct=0` 中转）。
