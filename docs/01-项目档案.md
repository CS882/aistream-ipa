## 扩展字段

### 架构决策摘要（为什么选 A 而非 B）

| 决策点 | A（已选） | B（未选） | 选择理由 |
|--------|----------|----------|---------|
| 技术栈 | Web 统一内核 + 四端壳 | Flutter 一套代码多端编译 | ① TV 端生态：Web 可由 TV 浏览器 / Android TV WebView 直接承载，Flutter 的 TV 支持弱；② 三端「分别设计布局导航」用独立 DOM 模块最直接；③ 本次运行环境无 Flutter SDK，A 可立即起服务验证「可运行」；④ 数据源缺失，A 的配置驱动可让需求方补完信息后**不重编译**即生效 |
| 架构 | 单体前端 + 单一 store + 适配层 | 微服务 / 多仓 | MVP 优先，四端一致性靠共享内核保证；服务端代理等属于「可延后」项，待 P-03 明确后再加 |
| 部署 | 本地零依赖静态服务（当期） | 云托管 / 多区域（可延后） | 发布所需包名、证书、素材均未提供，先保证可运行可验收 |

**「必须当期」**：统一内核、三端独立布局、数据源适配层契约、待补充项登记。
**「可延后」**：真实数据接入、播放器、服务端代理、原生打包上架、监控告警。

### 技术债务清单（已知妥协与待优化项）

1. 影视数据为骨架占位态 —— **刻意保留**，遵守「不得编造示例值」约束，非缺陷。
2. `capacitor.config.json` 的 `appId` 为空 —— 需求方未提供，原生打包前必须补。
3. `webDir` 目前指向项目根，正式打包应收敛到仅含静态资源的目录。
4. 无播放器实现 —— 本次范围仅「播放入口」。
5. TV 遥控器按键映射为常见兼容集，需实机按目标设备核对（P-29）。
6. 未做服务端 CORS 代理 —— 待 P-03 给出方案后补。
7. 无自动化 E2E 测试 —— 当前验收依赖 `npm run check` 静态自检、人工四端验收清单与无头浏览器 DOM 校验。
8. 顶部频道为参考图 UI 版式，未与内容源真实分类绑定（P-04 / P-33）；`fetchChannels()` 适配层已预留，但尚未接通频道渲染。
9. 平台能力表（`platform.js` 的 `capabilities()` / `config.js` 的 `PLATFORM_LAYOUT`）为声明式参考，三端布局已是独立实现，未依赖它做缩放。
