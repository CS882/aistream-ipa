## 一、唯一需要修改的文件

```
src/core/datasource.js   →   DATA_SOURCE 对象
```

其余文件（`src/core/store.js`、三端 `src/platforms/*`、样式、入口 HTML）**都不需要改**。

原因：四端只通过 `src/core/store.js` 取数据，`store.js` 只通过 `datasource.js` 取内容源数据。适配层把「内容源字段」翻译成统一内容模型后，三端渲染的是同一份模型。

## 二、当前配置状态

```js
export const DATA_SOURCE = {
  host: 'fnos.jiulingkeji.asia:8890',   // ← 需求方唯一已提供的信息

  protocol: null,        // ← P-01：换成需求方给出的协议
  apiBasePath: null,     // ← P-02：换成需求方给出的接口根路径
  endpoints: {
    channels: null,      // ← P-04
    list: null,          // ← P-05
    search: null,        // ← P-06
    detail: null,        // ← P-07
    play: null,          // ← P-08
  },
  method: null,          // ← P-09
  auth: null,            // ← P-10
  staticParams: null,    // ← P-11：接口要求的固定参数「名 → 值」
  headers: null,         // ← P-12
  pagination: null,      // ← P-13：{ listKey, dataKey, pageKey, sizeKey, ... }
  paramMap: null,        // ← P-36：内部语义参数 → 内容源真实参数名
  fieldMap: {
    id: null, title: null, poster: null, badge: null, subtitle: null,
    score: null, category: null, description: null, playUrl: null, episodes: null,
  },                     // ← P-14 ~ P-23：填「内容源真实字段名」，不是值
  allowMockData: false,  // 恒定，不得改为 true
};
```

> **重要**：上表里的 `null` 就是正确状态。需求方没给的值请保持 `null`，**不要根据常见命名去猜**，也不要填任何路径、参数名或示例数据。代码中的就绪检查会自动把这些项继续列为「待补充」。
>
> 跨域（P-03）不属于前端配置项，因此 `DATA_SOURCE` 里**没有** `corsProxy`，详见第七节。

## 三、填写规则

| 配置项 | 应填什么 | 备注 |
|--------|---------|------|
| `protocol` | 需求方明确给出的协议字符串 | 不填则 `baseURL()` 返回 `null`，不发任何请求 |
| `apiBasePath` | 接口根路径字符串 | 只填路径部分，host 已固定 |
| `endpoints.*` | 各接口路径；若需求方给出的是完整地址也可直接填 | 相对路径会拼在 `baseURL()` 之后，完整地址直接使用 |
| `method` | 需求方给出的请求方法 | GET 走 query，POST 走 JSON body |
| `staticParams` | `{ 参数名: 值 }` 对象 | 只填需求方给出的必要固定参数 |
| `paramMap` | 按能力分组的「语义名 → 真实参数名」对象 | **见下方专项说明**；未配置的语义参数一律不发送 |
| `headers` | `{ 头名: 值 }` 对象 | 防盗链 / 自定义头；POST 时若需求方未指定 Content-Type，本端按自身 JSON 序列化格式声明，可被此处覆盖 |
| `auth` | 需求方给出的鉴权结构 | 代码按 `auth.headers` / `auth.query` 透传，不推断鉴权逻辑 |
| `pagination` | 至少含 `listKey`（响应列表字段名）；详情若有包壳再填 `dataKey` | 其余分页字段按需求方给出的规则填 |
| `fieldMap.*` | 内容源返回的**字段名字符串** | 例如需求方说明「片名字段是 X」，才把 `title` 填成 `'X'` |

### 关于 `paramMap`（P-36，最关键的一条）

适配层内部使用的是语义参数：`nav` / `channel` / `keyword` / `page` / `id`。这些**不是内容源参数名**，代码绝不会把它们原样发出去。

`paramMap` 的结构是按能力分组，值必须是需求方给出的真实参数名（未给出就保持 `null`）：

```js
paramMap: {
  list:     { nav: null, channel: null, keyword: null, page: null },
  search:   { keyword: null },
  detail:   { id: null },
  play:     { id: null },
  channels: {},
}
```

- 只有值非 `null` 的语义参数才会发送，且使用需求方给出的名字。
- 值为 `null` 的语义参数**直接省略**，不会退化成内部名。
- `paramMap` 整体为 `null` 时，所有能力的就绪检查不通过 —— 这是刻意设计，避免在参数名未知时贸然请求。

> `fieldMap` 与 `paramMap` 填的都是**名字**（字符串），不是数据。代码用 `mapItem()` 把原始对象转成 `{ id, title, poster, badge, subtitle, score, category, description, playUrl, episodes }` 统一模型；任何未配置的字段对应值为 `null`，界面留空，不生成默认值文案。

## 四、运行时覆盖（可选，便于联调）

`datasource.js` 导出 `set(path, value)`，可在浏览器控制台临时覆盖，无需改文件：

```js
const ds = await import('/src/core/datasource.js');
ds.set('protocol', '<需求方给出的协议>');   // 尖括号为占位说明，实际填真实值
ds.set('endpoints.list', '<需求方给出的列表接口>');
```

> 这种方式只用于本机联调，正式配置请写回 `DATA_SOURCE`。**不要在代码里留下任何未经需求方确认的值。**

## 五、请求执行流程

```
四端 UI  →  store.js（统一业务逻辑）
              ↓
        datasource.js 的 fetchList / search / fetchDetail / resolvePlay / fetchChannels
              ↓
        readiness() 就绪检查：
          协议 / 根路径 / 方法 / 对应接口 / paramMap / id·title·poster 字段
          （play 额外要求 playUrl 字段）
              ├─ 不齐 → 返回 { status: 'unconfigured', data: [], pending: [...] }
              │          界面渲染「内容待接入」骨架态 + 待补充项计数
              └─ 齐备 → endpointURL() 拼地址
                          ↓
                     buildParams()：按 paramMap 把语义参数翻译成真实参数名，
                                    未确认的参数直接省略
                          ↓
                     透传 staticParams / headers / auth → fetch
                          ↓
                     parseResponse()：
                       列表类按数组解析（pagination.listKey）
                       详情 / 播放按单对象解析（pagination.dataKey 可选）
                          ↓
                     mapItem() 按 fieldMap 映射为统一内容模型
                          ↓
                     四端同时渲染真实条目
```

`statusSummary()` 提供 `{ configured, host, baseURL, pending, count }`：

- `configured` 只看 5 个能力的就绪检查，**与发布素材 / 版式文案等人工确认项解耦**；
- `pending` / `count` 仍完整列出 17 项待补充信息，方便追踪。

因此补完接口配置后，顶部状态条会变为「内容源已对接」，而版式、包名等仍会列在计数里，两者互不干扰。

## 六、播放入口的边界

本次交付的是**播放入口**，不是播放器：

- 点击「播放」→ `store.requestPlay(id)` → `datasource.resolvePlay(id)` → 调用需求方给出的播放接口、按 `fieldMap.playUrl` 取地址。
- 播放接口 / 地址字段未提供时，返回 `status: 'unconfigured'` 并提示「播放入口待补充」，**不会生成任何示例播放链接**。
- 拿到真实地址后如何播放（内置播放器、系统播放器、投屏、DRM 等）属于下一阶段范围，需需求方另行说明。

## 七、跨域与代理

浏览器直连内容源可能受同源策略限制。**跨域属于部署层 / 原生壳层事项，不是前端请求参数**，因此 `DATA_SOURCE` 中没有代理配置项，代码也不会凭空拼一个代理地址。可选做法（需需求方确认后实施）：

1. 内容源侧开启允许的 CORS 头；
2. 由部署层提供同源反向代理（在 Nginx / 服务端 / Electron 壳配置），前端仍请求相对路径；
3. 在 Capacitor / Android TV WebView 壳里配置允许的访问域。

无论哪种，都**不改变影视内容源地址**，仍只使用 `fnos.jiulingkeji.asia:8890`。
