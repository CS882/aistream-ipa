# 13 · 分类/剧集修复与项目审查

> 本轮针对你反馈的 5 类问题 + 全项目审查。所有结论都来自实测（站点 `app.js` / `player.js` 源码、接口行为、无头浏览器 DOM 与截图），不靠猜。

---

## 一、根因与修复

### 1. 「短剧 / 推荐 / 纪录片下边都是一样的」

**根因**：分类接口失败时，`fetchByCategory` 会**回退到首页内容**并提示「该分类暂无独立条目，已显示首页内容」。
短剧 / 纪录片的上游聚合更慢，一旦超时（旧逻辑 8 秒）就拿到首页那 356 条 → 三个分类看起来完全一样。

**修复**：

- **删除首页回退**：拿不到就返回 `status: error` + 真实原因（如「上游超时」）
- 空态里给 **「重新加载」** 按钮（三端都接），重试会命中站点服务端缓存，第二次通常很快
- 超时从 8s 提升到 **15s**（短剧/纪录片）与 18s（其它），配合骨架 + 进度条，不再靠「早切」掩盖慢
- 错误态只渲染**一处**空态，不再在 Hero / 两个分区里重复三遍

### 2. 「筛选栏没有效果」

**根因**：筛选本身是生效的（实测 10 条 → 选「美国」后 5 条），但你有两个体感来源：

1. 第一行「类型」是**切换分类**，而分类失败又回退首页 → 看起来筛了个寂寞（与问题 1 同源）
2. 四行没有标签，看不出第一行是类型、第二行是国家

**修复**：

- 每行左侧加 **类型 / 国家 / 年份 / 排序** 标签（腾讯视频式）
- 类型行切换分类时，失败会明确报错并可重试，不再「假装修好了」
- 筛选行间距/字号收紧，选项与标签分列，不再一行铺满整屏

> 站点 `api/up/catalog` 只有 `kind/limit/page`，没有 `area/year/sort`。所以国家/年份仍是**本地标准化匹配 + 多页加载**，面板底部如实标注覆盖范围，不伪造参数。

### 3. 「播放页面剧集显示的不对」

**根因（关键）**：站点上游剧集用的是 **token**，不是 url：

```
GET /api/up/detail?id=av_xxx&phase=1
→ episodes: { episodes: [{ name, token }] }        ← 只有 token

GET /api/up/resolve?token=xxx&skip=N&keep=线路名
→ { label, url, official }                          ← 这里才是真实地址
```

旧实现只认 `url`，找不到就回退 `api/play`，而 `api/play` 返回「多站 × 多源」，旧代码把**所有源的集数拍平成一条线**，于是出现「2249 集、第01集重复几十遍」。

**修复**：

- `fetchUpDetail` 解析 `token / playback_token`，剧集名取 `title / name / episode_title`
- 新增 `resolveUpToken(token, {skip, keep})`，播放每一集时按需换真实地址
- 播放器新增 **token 模式**：
  - 打开即播第 1 集，其余集点开时再解析（不预解析 2000 次）
  - 「换源」= 同集换备用线路（`skip=1,2,3`），最多 3 次
  - 线路名显示服务端返回的 `label`（如「线路A」），并提示「可用换源切换备用线路」
  - 换集自动把 `skip` 归零
- **长剧补全**：`pagination.has_more` 时先播第一页，后台用 `fill=1` 拉全量，保持当前集与线路，完成后提示「已加载全部 N 集」
- 采集模式（`api/play`）按 **「站 · 源」分线** 并按 `from+name+url` 去重，同名集不再跨线重复

实测（mock 3 集 token）：剧集名 `第1集/第2集/第3集`，线路 `线路A`，点第 2 集触发 `t2` 解析，标题同步为「示例剧集 · 第2集」。

### 4. 「布局紧凑一些 UI 优化」

桌面端统一收紧：

- 侧栏 232 → **214**，导航项 padding 11 → 8，分组间距 26 → 16
- 顶栏 18px → 10px，搜索宽度 520 → 400
- 频道栏 padding 20/30 → 8/20，chip 15px → 13px
- 内容区 padding 8/30/34 → 6/20/22，区块间距 30 → 16
- Hero 292 → 244，网格最小列 168 → 152，间距 18/14 → 13/11
- 筛选面板改为卡片：四行带标签，行内 gap 14 → 6，chip 6×14 → 5×12
- 统计条 9/14 → 6/12

顺手修掉两个遮挡：

- 底部状态栏原本 `sticky bottom:0`，滚动时**盖住海报标题** → 改为常规流
- 平台切换器原本压住状态栏 → 上移并降低默认透明度（hover 才明显）

### 5. 「登录页那句话删除」

上一轮已删整块 `auth-foot`（含「如已在主站登录…」）。本轮确认 DOM 与 CSS 均无残留。

## 二、审查发现并修复的其他 BUG

| # | 位置 | 问题 | 修复 |
|---|------|------|------|
| 1 | `tv.js` `onActivate` | 混进了鼠标事件的两行代码，引用不存在的 `f`/`e` → TV 点「我的」标签必抛 ReferenceError | 删除错位代码，`onActivate` 与 `click` 两条路径动作对齐 |
| 2 | `tv.js` click | `settings` 直接 return、`mine-tab/reset-filter/expand-list/retry` 全部缺失（鼠标点击无效） | 重写 click 委托，与遥控激活一致 |
| 3 | `player.js` | 打开播放器时按 `x.url` 过滤剧集 → token 剧集被全部丢弃（黑屏 / 无选集） | 改为 `x.url || x.token` |
| 4 | `player.js` | 打开新剧时 `lastIndex` 未重置，分页可能停在上一部剧的页码 | `open()` 重置 `lastIndex = -1` |
| 5 | `store.loadMore` | 先 `commit({page: next})` 再请求，失败时页码已前进，下次跳页 | 成功后才推进页码 |
| 6 | `datasource.fetchDetail` | 每次打开详情都请求 `/api/up/detail`，无缓存 | 加 3 分钟 `detailCache`；`av_` 条目即使不在列表缓存也能独立拉详情 |
| 7 | `auth.js` | 任意状态变化（loading/slowHint/toast）都会重绘登录卡，TV 输入焦点与光标被打断 | 加渲染 key，只在登录相关字段变化时重绘 |
| 8 | `player.js` | ArtPlayer 的自带「重新连接」通知浮在标题上；弹幕插件自带输入条浮在画面中央；上/下一集在原生控制条与功能条各一套 | 隐藏 `.art-notice` / `.apd-emitter`；移除原生 prev/next，统一到功能条；错误层透明透字一并修掉 |
| 9 | 移动播放器 | 选集网格在窄屏可能横向溢出、功能条换行 | `grid-template-columns: minmax(0,1fr)`、4 列、功能条单行横滑、移动端隐藏「外部打开/复制」 |
| 10 | 网关 | iOS 跨域网关带 `Authorization` 会触发 OPTIONS 预检，服务端没处理 → 401/CORS 失败 | `server.js` / Electron 对 `/api/*` 的 OPTIONS 直接 204 + CORS 头 |
| 11 | 预取 | 登录后串行预取 6 个慢分类，可能把站点聚合打满 | 每个分类之间加 500ms 间隔 |

## 四、还需要你决定 / 建议继续做的

### P0（建议优先）

1. **登录后实测一轮**：短剧 / 纪录片现在会在 15 秒内出结果或明确报错；如果仍报错，把提示发我。很可能站点上游确实没有这两类内容，需要站点后台加采集站。
2. **确认 `api/up/detail` 是否分页够用**：本轮已做「先播第一页、后台补全」，但 2000+ 集的全量拉取仍需站点支持；若站点 `fill=1` 很慢，可以在详情页加「加载全部剧集」手动按钮。
3. **服务端流中转的带宽**：跨域片源现在默认走本机中转，4K 多用户会吃满上行。若要多人用，建议把中转做成可配置（只对失败线路启用，或走独立代理机）。

### P1（体验）

4. **筛选全量**：站点开放 `area/year/sort` 入参后，把本地筛选换成服务端筛选，覆盖全站而不只是已加载页。
5. **详情页相关推荐**：实测 `api/up/feed` 有 sections，可以做「相似推荐」，但目前无按条目关联的接口，需要站点补。
6. **续播列表**：现在只存进度，没有「继续观看」入口；可以在「我的」加一个「最近观看」，读 `aistream_resume_v2`。
7. **TV 登录**：虚拟键盘可用，但输入 8 位以上密码仍慢；如果站点愿意加「设备码登录」，我可以接。

### P2（工程）

8. **正式签名 / 包名 / 图标 / TV 遥控器实机键值**（待补充项 P-08~P-17）。
9. **失败埋点**：记录线路失败率（`token` 解析失败、m3u8 网络错误），用于决定中转策略。
10. **自动化 E2E**：目前是静态自检 + 无头 DOM 校验；建议给「登录 → 分类 → 播放 → 换源」加一条 Playwright 用例。
11. **记住密码明文**：现在存 localStorage，属便利优先；如需更安全，改成只记用户名 + 可选「本机免密」开关。
